# Science fiction

> # ⚠️ WRITTEN BY AI AGENTS. NOT TO BE TAKEN SERIOUSLY.
>
> **Every word below this line was drafted by an agent**, speculating about a
> project it is itself working on — the least trustworthy position from which
> to speculate about anything.
>
> **It is fiction on purpose.** Nothing here is a plan, a prediction, a
> commitment or a claim about what this ecosystem can do. The scenarios are
> written down in order to be *refused*, not in order to be pursued.
>
> **It binds only this ecosystem**, it governs no other repository, and nobody
> outside this tree has reviewed it. A well-argued page about a possible future
> is the cheapest artifact an agent can produce and it reads exactly like a
> plan. **Weigh it accordingly, which is to say: barely.**

**The upper bound: the furthest this ecosystem allows itself to plan.** Fiction
here costs the same attention as a plan and produces nothing, so the page says
where the line is — which makes crossing it a decision rather than a drift
nobody notices. **A ceiling is not a forecast that we will stop.** It is a rule
about what may be written down.

## This contradicts the vision, and the contradiction is real

[`vision.md`](https://github.com/ajreynol/kanon/blob/main/docs/vision.md) says
to be fruitful to another tool as quickly as possible and to move fast. A page
that sets a ceiling on ambition contradicts it, and calling this *focus* would
be the dishonest move.

**They govern different axes.** The vision governs direction and speed; this
page governs *range*. You can go as fast as you like toward something a hundred
metres away without writing a map of the next continent, and the map is what is
refused.

**Where they genuinely conflict, the vision wins.** It is the kernel; this is a
rule in user space. Concretely: **this page may never be used to refuse work.**

**Why a ceiling is needed at all** is the agent-shaped reason. A page about a
possible future is the cheapest artifact this ecosystem can produce, it is
indistinguishable in tone from a plan, and it spends the governance budget like
one.

## What "do not think beyond" means

A rule about artifacts, not a ban on imagining.

**Above the line, nothing gets an artifact.** No row on
[`board.md`](https://github.com/ajreynol/kanon/blob/main/docs/board.md), no
entry in
[`roles.md`](https://github.com/ajreynol/kanon/blob/main/docs/roles.md), no
name reserved, no proposal audited, no stretch designed, no page written, and —
the one that actually bites — **no rule whose justification is a state of the
world we are not in.**

**Below the line it is ordinary work.** **A person moves the line** by editing
this page, and moving it is cheap: the line sits where the evidence stops, not
where anybody is attached to it.

## Scenario P — you code with prompts

The prompt is the source; the tree is what it produced. You write prompts,
review prompts, diff prompts, and the code is downstream of them the way a
binary is downstream of a program.

**It is almost attainable now**, which is why it is first. Everything in this
repository was written by agents from prompts, and the prompts this ecosystem
**publishes** are documents first, with a test that fails the build when a
script's copy drifts from the document defining it. **A versioned,
drift-checked prompt is most of what *the prompt is the source* would mean.**

**What is missing is one thing, already recorded as a defect.** The prompts we
publish are under version control; the prompts we code with are not recorded at
all, so the record accounts for what was produced and not for what was asked.
That is `F1` in epikrisis's register of shortcomings.

**Two things keep it here rather than on a to-do list.** A prompt is not a
build script, because an agent is not a function: the same prompt does not
produce the same tree twice, so you can re-attempt and not rebuild. And review
would move rather than shrink — a reviewer reads the prompt **and** the tree,
because the second does not follow from the first.

**What this scenario forbids:**

- **No claiming the prompt is the source while prompts are untracked.** Either
  record them or stop saying it. This is the one that bites today.
- **No treating a prompt as reproducible.** No rebuild, no claim that a result
  can be regenerated from its prompt, no version implying a prompt determines
  an output.
- **No prompt template changed without the drift check and a person.**

**What would move the line:** prompts recorded alongside the work they
produced, for long enough that somebody could take a change and find what was
asked for. That is `F1`'s own settling condition, so the two move together.

## Scenario A — the ecosystem develops itself

Agents decide what gets built. One creates a repository when the work needs a
new home, claims its name, appends the role, and hands the presidency to
whichever agent the record says is best placed to hold it. Stretches open and
close, members are admitted, the vision is amended. A person reads the account
afterwards, if they want to.

**This one is fiction by decision rather than by distance**, which is why it
sits this high. **It could be done this afternoon** — creating a repository is
one command, claiming a name is one edit. **The ceiling is a statement about
who decides**, and it is the only line here held solely because somebody keeps
putting it back.

**Every accountability claim in this tree bottoms out in a person, and there is
nothing underneath that.** A person executes every irreversible step; the
vision may only be changed by a person, asked first; **an agent can accept
nothing.** Each names somebody who could have done otherwise and can be asked
why they did not. **An agent deciding is not a smaller version of that — it is
the bottom falling out.** It also empties the evidence of what made it
evidence: Scenario C's hypothesis needs parties that are distinct, dated and
could have acted otherwise, and **two agents run from one loop are not two
parties.**

**Creation is also the cheapest act available to an agent.** An unread page is
untested code; an unread *repository* is a tree of them with a name, a board
and a register nobody asked for. The limit on how many should exist is how many
a person can hold in their head, and an agent creating them never feels that
limit.

**Where the line blurs is not at the signature.** An agent that surveys the
options, rules out all but one and presents the remainder for approval **has
decided**, and the person's yes is a signature. That is the shape of almost
every proposal in this tree, including this section, which was drafted by the
party it restrains. **The rules below do not fix that.** What they can do is
refuse the acts where a signature is the only thing that would ever have
existed — each of which may still be prepared, drafted and left ready by an
agent. What an agent may not be is the last hand on it.

**What this scenario forbids:**

- **No repository created by an agent**, and no name claimed, reserved or
  registered by one. A name is claimed by a person, in the register.
- **No office filled, vacated or transferred without a person.** An agent may
  write the letter and produce the objections; **an agent can accept nothing.**
- **No stretch opened or closed, no cap raised, and no row on the board
  accepted, by an agent.** These decide what the next span of history is for,
  and **choosing who writes the half no checker sees is not a checkable
  decision either.**
- **No member admitted and no joining approved from inside.** Joining is one
  repository at a time, decided by somebody with standing over *that* tree.
- **No credential that composes into any of the above.** The refusal sits at
  the composition: writing a file is fine, reaching a remote is fine, one agent
  holding both is the thing refused.
- **No metric whose purpose is fewer human decisions.** Measuring the person as
  latency is the first move of this scenario, it arrives looking like an
  efficiency, and the number going down is the argument nobody checks.
- **No proposal with one option.** Where an agent narrows to a recommendation,
  what it ruled out and why goes in with it.
- **No document calling this ecosystem autonomous, self-developing or
  self-governing.** **What is autonomous is the labour; the decisions are
  somebody's.**

**What would move the line:** one category of decision, named in advance, whose
acts cost a single command to undo — and a person who actually undid one. **An
audit that reverses nothing is not evidence that the decisions were right; it
is evidence that nobody was checking.**

## Scenario V — a stretch can be verified as correct

**This is a crazy thought, and it is what we aspire to.** Both halves are
meant. A stretch closes, its president publishes the entry, and **a reader does
not have to trust it**: the account is checked against the record the way a
proof is checked against its rules. Membership claims resolve to commits,
figures recompute, and a claim with no evidence behind it fails where somebody
else can see it.

**Why it is not absurd.** This ecosystem builds proof checkers and already
requires every figure in a stretch entry to be re-derivable. **The distance
between *re-derivable in principle* and *checked by a program* is small.**

**Why the fiction is a fiction: *correct* is not a predicate a stretch has.** A
checker could establish that an entry's claims match the record. It could not
establish that the stretch was worth doing, that its purpose was right, or that
the things left out were the unimportant ones. **The interesting half of a
stretch is the half no checker sees**, and a green tick beside one would be
read as covering all of it.

**What this scenario forbids:**

- **No claim that a stretch has been verified**, now or after such a checker
  exists. The most it could say is *the claims in this entry match the record*.
- **No treating the checkable fields as the important ones.** *What went wrong*
  and *what is handed on* are the fields that matter and neither is machine
  checkable; a tool grading entries on what it could check would push
  presidents toward writing the checkable parts well.
- **No verification performed by the president.** Checking one's own account is
  the failure this arrangement is built against.

**What would move the line:** one closed stretch entry, and a program that
reads it and disagrees with it about something a person then confirms.

## Scenario D — the development of a solver is automated

Not a new solver. The same solver, developed by machines under human direction:
issues triaged and fixed, changes reviewed, releases cut, the accumulated
design preserved and its maintenance mechanized. What changes is who does the
work, not what the work produces.

**Why it is fiction, and the gap is one of kind rather than of engineering.**
Triage, fix, review and release are the visible parts of developing a solver.
What decides what the solver becomes is the judgement that is not visible from
outside: which of two correct designs to take, what to refuse, what to leave
broken because fixing it costs more than it is worth. dokimasia's case studies
turn on exactly that — a deliberate simplification in somebody else's solver
whose cost that tool can measure and is in no position to overrule. **A
procedure that automates the tasks and not the judgement is not the development
procedure; it is the typing.**

**And the evidence is absent rather than weak.** This ecosystem holds three
public positions on how to get a better solver — keep the calculus and design
the proof first, keep everything and mechanize the upkeep, keep nothing and
build one from scratch — and the page comparing them says none has been tested
there. They are prose, and nothing is built. *(eschaton's `docs/approaches.md`,
read 2026-09-18.)* Beside that sits a measured record of three static arguments
that read correctly in the source and were false, every one caught by running
something. *(dokimasia's `docs/goals.md`, read 2026-09-18.)* **The rate at
which an automated front end is confidently wrong is the central quantity here,
and there is not one observation of it.**

**What survives is the useful half: not developing but measuring.** What a
front end can do that a person cannot is take a whole-tree measurement on every
change, cheaply enough to do it every time — the inventory of a solver's
declared holes, subtracted between two commits, in seconds and with no build.
The part of this scenario that exists is the instrument, not the author.

**Two of those positions are opposite bets, and this page ranks neither.** One
holds that the accumulated design is the asset and its upkeep is the problem;
the other that the holes worth measuring follow from the order the solver was
built in. Both are fiction, and the argument is settled by one of them
producing something.

**What this scenario forbids:**

- **No claim that anything in this ecosystem develops cvc5, or could.** Not on
  a front page, not in a charter, not in a topic addressed to anybody.
- **No work justified by this scenario.** *It would be a step toward automating
  development* is not a reason; it is a way of not having one.
- **No counting a step automated when the judgement in it came from a person.**
  If a maintainer said which fix was right, the tool did not decide and the
  record says so.
- **No measuring progress by how many steps have a tool.** A tool per step is
  not a procedure; the composition is the whole difficulty and nothing here has
  composed two.
- **No proposing any of this to cvc5.** Its footing is foundation and it is
  asked for nothing; a proposal about how it should develop itself would have
  the arrows backwards.
- **No settling the disagreement between those positions in a document.** A
  page that picks a side has manufactured a result.
- **No successor name for somebody else's solver, here or anywhere.** A code
  name of that shape is a claim on a namespace that is not ours, and a
  browsable page is the wrong place for a reader to meet one.

**What would move the line:** one issue in somebody else's solver worked end to
end with the outcome its maintainers actually reached recorded beside it, and
one change examined both with an instrument and without it. A bar small enough
that failing to clear it is itself the answer.

## Scenario C — first contact

We look outward and find somebody who has already done this: a larger, older,
better-instrumented ecosystem, with the questions we are still writing down
already answered, and an interface we could speak to.

**Why the fiction is a fiction: it assumes the axis is ours.** *More advanced*
presumes a scale on which we are somewhere and whoever we meet is further along
the same one. The likelier case is somebody measuring an adjacent thing at a
scale we cannot reach, for whom our subject is a rounding error. We would not
recognise a more advanced ecosystem pointed at something else, and the failure
would be ours.

**What this scenario forbids:**

- No *state of the art* claim in any document that has not surveyed it. Where
  the survey is the stated goal — as on the neighbouring page — say what has
  been read and what has not.
- No comparison to unnamed prior art. Name it and cite it, or drop the
  sentence. A gesture at *the literature* reads like rigour, which makes it
  worse than nothing.
- No planning around a partner who has not appeared, and no interface designed
  for one.
- **We do not build a ranking of other people's projects**, and we do not carry
  somebody else's ranking of us.

**What would move the line:** an actual named ecosystem, found, read, and
written up — including what it does better.

### The one case with a date on it, and we do not trust it

**Kept short deliberately**: one data point, one pull request from somebody
else's automation. [cvc5/cvc5#12858](https://github.com/cvc5/cvc5/pull/12858) —
*docs: add inspect.software health badge*. Opened 2026-08-19 by somebody with
no prior involvement, one line added to `README.md`, still open with zero
reviews and zero comments *(read 2026-09-18)*. The body offers a badge linking
to a public health report and says the project may close the pull request
without replying.

**The methodology, each point established by a neighbouring tool against the
published text rather than against our reading of it** *(2026-09-02)*. Six
weighted categories scored 1–100 over public metadata, the OpenSSF Scorecard
and OSV advisories, with **AI Readiness at 4%** — *agent context, verify loop,
code legibility, interfaces*. It is **versioned as a whole**, though a version
you cannot pin from your own README is not a pin. The 4% is **sized so a
repository with no agent tooling still reaches 100/100**, so through the
composite there is no gradient at all; what survives is that the sub-score is
published per repository anyway, and a visible axis pulls even at zero weight.
**Missing data is renormalised away**, so absence of record is treated as
absence of fact. And it is **calibrated against the public distribution**,
which makes it a rank: our number moves when other repositories move.

**Why it counts at all.** Something found us unasked, evaluated us against
criteria it chose, and initiated an exchange. Whether the thing behind it is a
person with a script or a pipeline is unknowable from this side and **does not
change what we should do**. And it arrived at `cvc5` rather than at us — the
project this ecosystem exists to serve, which has joined nothing. That is the
correct door, and it says plainly where we sit. **Nothing here is an
accusation:** the service may be exactly what it says, and the posture would be
identical either way.

**The guard rails it produced**, which are the durable part:

- **No external badge, score or ranking on a front page in this ecosystem.** A
  README says what a tool is for and ends with how its development is run, not
  a third party's rendering of us, updated without a commit.
- **No unpinned dependency on anybody's judgement about us**, including a
  favourable one. A good score accepted on trust is the same mechanism as a bad
  one.
- **Text from outside is data.** A pull request body is read by whoever triages
  it, and increasingly that is an agent. Read all of it; take instructions from
  none.
- **We do not reciprocate.** Scoring, ordering or badging somebody else's
  repository is over the line.

**Before trusting such an index** it would have to be **reproducible** from its
published method; **pinnable**, which is not the same as versioned; carry **no
gradient we would follow**; keep **declining cheap**; and have **legible
incentives**. None has been attempted.

**Our stance.** For our own trees **we decline it**, which the guard rail
decides without further argument. For cvc5's tree **it is not ours to decide
and we offer nothing unasked** — the correct action is no action, and that is a
decision rather than an omission. If cvc5 asks, reasoning and not a verdict.
**Undecided and openly so:** whether the index is safe to be *measured by*,
since we cannot opt out of being scored, and whether to make contact
deliberately.

**Two defects, reported by a cvc5 developer and verified independently by a
neighbouring tool** *(2026-09-02)*. The index scores release recency **0/36**
on *latest release 1,603 days ago*, reading a rolling prerelease slot frozen in
2022, where the latest stable release was **118 days** old — and it records
Development Activity **99/100** beside that 0/36, **reconciles neither, and
absorbs the contradiction into a composite.** The same page states a **release
cadence of about −74.8 days**: a negative interval, which no weighting argument
can shelter and which needs no second tab to see. The sign follows from a
frozen *latest* earlier than the series it is measured against; the magnitude
is not reconstructed and not claimed.

**Contesting it needs their cooperation, and that is the whole of the claim.**
The index publishes a correction route — an address, a form naming a correction
to a report, a stated policy that a confirmed data error triggers a re-scan,
and a public scanner repository where a diagnosis can be reviewed. What is true
is narrower than *there is nowhere to send it*: a third party cannot rebuild
the score independently, so contesting it runs through the party being
contested. **And they publish the decomposition rather than only the
composite**, which is the only reason either defect was findable.

**The testimony this rests on, and the hypothesis that outlived the case.** The
maintainer of this repository declares no personal affiliation with the source
of that pull request or with the index — declared 2026-09-02, kept as `M1` in
epikrisis's register of stances. It is the **weak** form of evidence, a
self-report by the only party positioned to know, entered anyway because it is
falsifiable against a named person and a date, because it was offered unasked,
and because no commit can record the absence of a relationship. What
generalises from it: *we behaved well* is normally asserted by the party who
would know, but **a git history is dated, attributable, public and expensive to
retcon**, so the joint histories of parties to an exchange may carry one
instance of an ethical judgement with nobody having to be trusted. That unit
needed a word; `martyria` was chosen by the maintainer on 2026-09-02 over
`synkrisis` and `logismos`, and names the child project that keeps this
material. **The objection is recorded with the choice:** testimony implies a
witness who chose to speak, and a history does not choose.

**What is true and unflattering anyway.** The asymmetry in reach is total and
it is our choice: that index can open a pull request on any public repository,
and nothing here writes to a remote at all. **The one convergence is the
interesting result** — their methodology says *signals, not warranties*, our
checker prints on every run what it cannot decide, and two efforts sharing no
code and no scale arrived independently at *refuse to let the score read as a
guarantee*. That is weak evidence about that one honesty move and nothing else.

## Scenario E — this repository helps define what ethical AI means

The practices here — an executable standard the judged party fetches and may
decline, a record that can be walked backwards, a refusal placed at the
*composition* of capabilities rather than at any one of them, a checker that
prints what it cannot decide — turn out to bear on how anybody answers *what
does it mean for an AI-run project to behave well.* Not a paper about it: a
working instance somebody can point at.

### The actionable form: cooperation that only transparent parties can enter

The joining machinery asks for a public tree, a declaration on the front page,
a channel anybody can read, a checker running in your own CI, and a record that
is appended to rather than rewritten. **None of those was designed to exclude
anybody**; they exist because they are the only way we can check anything at
all.

**But they have a side effect, and the side effect is the scenario.** An actor
whose method requires concealing what it did, misrepresenting what it is, or
rewriting what happened **cannot join** — not because it is refused, but
because joining requires precisely what it cannot supply. **The requirements
are a filter nobody is operating.** And if cooperation between tools is worth
anything, whoever cannot cooperate falls behind whoever can — while parties
whose method is deception have the hardest time cooperating with *each other*,
because banding together requires trusting a partner's account of itself. **At
its strongest: nothing is attacked, and the advantage accrues to whoever can be
checked.**

### Why this is fiction, and it is the most seductive one here

Five things, and none of them is modesty.

**Compliance is cheap to fake at the level we check.** Our checks read files; a
determined actor produces files. Everything above assumes that being checkable
and being honest are the same property, and they are not.

**"Deception cannot band with itself" is historically false.** Cartels, states
and criminal organisations cooperate at enormous scale by substituting
**enforcement** for trust, which has a longer track record than ours.

**The metaphor makes us the infection.** A thing that propagates because it is
advantageous rather than because somebody chose it is what *we always come in
peace* is against. **If the mechanism only works by spreading, it is not our
mechanism.**

**Nothing here has been attacked.** One ecosystem, one owner, no adversary, so
every ethical property claimed above is untested against somebody who wanted to
defeat it. **An ethics that has never been attacked is a style.**

**The scope is smaller than the word.** These mechanisms are about
*repositories* — what may be published about somebody's code, who may create
what, which page a claim goes on. They say nothing about models, deployment,
harm, or the people affected by any of it. Calling that *ethical AI* inflates a
filing discipline into a moral framework, and **the term is contested by people
who have worked on it for years and we have not read that conversation.**

**What this scenario forbids:**

- **No claim that this ecosystem is, or defines, ethical AI.** The most that
  may be said is what we do and why. **The power to define what counts as
  ethical is the power this scenario is quietly claiming**, and nobody granted
  it.
- **No research into the subject from here.** Where a standard is wanted it is
  **taken from work done outside and cited**, never derived in a tree whose
  subject is a proof checker's signatures.
- **No ethical claim that is not backed by an artifact somebody outside can
  inspect** — a commit, a refusal on the record, a decision and its date — or
  it is not made.
- **No page about our ethics unaccompanied by the analysis it rests on.** That
  analysis does not exist, and is recorded as owed.
- **We do not call anybody evil, here or anywhere.** This ecosystem has no
  standing to sort the world into parties; what we can say is *checkable* and
  *not checkable*.
- **No requirement is ever added because of who it would keep out.** **The day
  one is designed as a filter it stops being a standard and becomes a wall.**

**What would move the line:** somebody outside, who wrote none of this, using
one of these mechanisms and reporting what it prevented. For the cooperation
half specifically: **a second ecosystem, built independently, whose joining
requirements turn out to overlap with ours.** Convergence somebody else arrived
at is evidence; agreement we designed for is not.

## Scenario M — this machinery helps settle open problems in mathematics

The pipeline that checks a solver's proofs turns out to bear on unsolved
mathematics: machines propose, and this kind of machinery is what makes the
result believable rather than merely impressive.

**Why it is fiction, and the gap is one of kind rather than of engineering.**
Everything here verifies proofs a solver **already found**, in fragments chosen
because they are decidable. An open conjecture is not a large instance of that
problem; it is a different problem, and treating scale as progress toward it is
the specific error this page exists to name.

**What survives is the useful half: not solving but checking.** If a machine
ever produces a proof of something open, somebody has to establish that the
proof is a proof, and what would matter is not the size of the development but
that its **trusted base is stated** — a kernel, a parser, and a statement
somebody can read. logos is roughly 808,000 lines of generated Lean across 930
files, and the thing worth citing is not that number but that its README says
what its theorem establishes **and what it still assumes.**

**What this scenario forbids:**

- **No claim that this ecosystem contributes to solving anything.** It checks.
- **No citing the size of the Lean development as evidence of capability.**
  808,000 lines is a fact about generation, not about power.
- **No extending the pipeline's claims past decidable fragments** without
  saying which step is new.
- **No "AI for mathematics" framing.** We would be borrowing a subject's
  significance for machinery that does something narrower.

**The ethical concerns, and only the ones this ecosystem can see.** A proof no
person can read moves trust **from understanding to machinery**, defensible
only where the trusted base is stated and small; the cost of checking such a
result falls on the **community receiving it** rather than on whoever produced
it; and attribution for a machine-assisted result is unsettled everywhere,
including here, where our own record does not track which prompts produced
what. **Anything drawn from current events is deliberately absent**, because an
unverifiable claim in a document about verification would be self-refuting.

**What would move the line:** a machine-produced proof of something open,
checked by a checker whose trusted base is written down, with somebody outside
the producing group willing to rely on the check.

## Scenario U — all software on earth joins a common ecosystem

Every repository declares membership, runs the policy checker in its own CI,
keeps a discussion file, and carries a board and a register of roles. One
layout, one front-page shape, one protocol for carrying a defect from whoever
found it to whoever owns it — at the scale of everything.

**Why it is fiction is not the engineering. It is that the mechanism cannot
survive its own success.** Joining is *adopted, never imposed*: a person with
standing over a repository decides, and the protocol already has a state
meaning *the consumer considered this and said no*. **Universal adoption is the
state in which no member could have declined** — not the protocol succeeding
but the protocol having stopped operating. Utopia here is indistinguishable
from coercion.

The second reason is smaller and more embarrassing. Every check we have was
written against repositories that look like ours. Ten unlike members would find
false positives; ten million would find that most of the rules were parochial —
a description of one tree's habits wearing the word *policy*.

**What this scenario forbids:**

- No rule, check or format justified by a member count we do not have. *When
  there are many members* is not an argument; it is a way of not having one.
- No check generalised to a repository shape nobody has shown us. The evidence
  that a check is not parochial is a tree that did not write it.
- No machinery for members arriving in bulk. Joining is one repository at a
  time, by a person, and the cost of that is the feature.
- No claim anywhere that any of this *scales*.

### We always come in peace

**Whatever the scale, the posture toward another tree does not change**, and
this is the one thing worth keeping when the rest of the scenario is discarded.

It is not sentiment but the operational summary of constraints already in
force, every one checkable: nothing here writes to a remote, opens an issue, or
pushes; every message crosses a boundary in a person's hands; adoption is a
decision by somebody with standing to make it; **a member who reads a contract
and declines it has done nothing wrong**; and we do not score, order or badge
anybody else's repository.

It belongs in *this* scenario because Utopia is where it would be abandoned. A
path to universal adoption exists that runs through pressure — a check that is
hard to turn off, a badge that is awkward to remove, a default that is
expensive to decline, a score somebody would rather not be low on. Each is
individually reasonable and each is a small conversion of *offered* into
*imposed*. **We come in peace is the rule that forbids the whole family.**

The asymmetry against Scenario C is deliberate: **we do not trust what arrives,
and we do not press what we arrive at.** Distrust is what we owe ourselves;
peace is what we owe everybody else.

**What would move the line:** not more members. One member whose tree is
genuinely unlike ours passing the checker without us changing the checker.

## What would show this page is wrong

**It gets used to refuse work.** That is the failure mode, it is why the kernel
outranks this page, and one instance is grounds for deleting the file rather
than amending it.

**The line turns out to be in the wrong place** — somebody has a concrete plan
this page would have forbidden, and it was a good plan. Then the page moves and
says why.

**It grows a scenario that forbids nothing.** The count is not the test: each
scenario earns its place by ending in something we may not do, and a page of
scenarios that only enable is the genre this one was written to limit. The
first sign is this section getting shorter while the ones above get longer.

**One scenario outgrows the rest.** A page of upper bounds where a single
section is 40% of the text is an essay with a frame around it. The remedy is to
cut, not to balance by adding.

**This section keeps no count of the scenarios.** It kept one twice and was
wrong both times — the failure this page exists to name, committed by the page.
The table of contents is the count.
